# Package Split

## Status

Accepted. Nothing is published yet: no Packagist entry, tag or split repository exists ([Release](0031-release.md)).

## Context

Only serving needs the extension ([Composer Metadata](0026-composer-metadata.md)). The ingress client and the test harness run without it. As one package, the SDK could either require the extension, and so force it on every user of the parts that never load it, or only suggest it, and so never let Composer check it for the users who serve. The official SDKs ship the same parts as separate packages: TypeScript's `@restatedev/restate-sdk-clients` and `@restatedev/restate-sdk-testcontainers`, Java's `sdk-testing` module.

The SDK and the ingress client share a few types (`Target`, `Serde`, `TerminalError`, …). Either the ingress package depends on the SDK package, which then cannot require the extension, or the shared types live in a small common package both depend on.

## Decision

Vendor `restate`, and these packages:

| Package | Namespace | Contents |
| --- | --- | --- |
| `restate/sdk` | `Restate\` | Handlers, the endpoint, everything that serves; requires `ext-restate` and `restate/common` |
| `restate/common` | `Restate\` (shared types only) | The types the SDK, the ingress client and typed ingress clients share |
| `restate/ingress` | `Restate\Ingress\` | The [Ingress Client](0022-ingress-client.md), no extension |
| `restate/testing` | `Restate\Testing\` | The [Test Harness](0023-test-harness.md), a dev dependency for users |
| `restate/ext-restate` | `Restate\Extension\` | The extension's PIE package, `extension/composer.json`: prebuilt binaries only ([Prebuilt Extension Binaries](0030-prebuilt-extension-binaries.md)) |

1. **Layout: `packages/<name>/`, wired by a Symfony-style root.** Each package is a directory `packages/<name>/` (`common`, `sdk`, `ingress`, `testing`) with its `composer.json` and `src/`. The root `composer.json` is **`restate/monorepo`** (`type: project`, never published): it `replace`s every `restate/*` package with `self.version`, autoloads every `packages/*/src/` (PSR-4), and `require`s the union of the packages' third-party requirements with the same constraints (plus the development tools, the optional dependencies the packages suggest, and the extensions they require except `ext-restate`). So there is one `composer install`, one `vendor/`, one autoloader and one `composer check`. The root never requires `ext-restate`: contributors build the extension after installing (`composer build:extension`), and the test-services images install the same way.
   - **Not path repositories.** A root that `require`s the packages through Composer path repositories would install `restate/sdk` and with it `ext-restate`, so the root would need `config.platform.ext-restate` to pretend the extension exists; it would symlink each package into `vendor/`, and record per-package references and branch-derived versions in `composer.lock` that change with every commit or branch. The replace-and-autoload root has none of that; what it does not exercise (each package's own `composer.json`) is checked statically (decision 9) and by loading each package with only its requirements.
   - **Not per-directory `composer.json` files over one shared source tree** (Symfony's own layout): a subtree split takes a directory, so every package needs a directory of its own.
2. **Namespaces and class names do not depend on the package.** `restate/common` and `restate/sdk` both map `Restate\` to their own `src/` (Composer searches both); `bin/check-packages.php` fails when both define the same type. The other packages map their namespace (`Restate\Ingress\` → `src/`, …) as usual. Moving a type between packages is moving its file (and the requirement); users' code does not change.
3. **What `restate/common` holds.** A type goes there when packages that do not require each other both need it (the SDK and the ingress client, or the SDK and typed ingress clients), and it uses nothing outside `restate/common`:
   - for the ingress client: `Serde`, `JsonSerde`, `Target`, `TerminalError`, the `Exception` marker interface, `Internal\FlowControlKeys` (scope and limit key checks) and `Internal\TerminalMetadata` (metadata checks);
   - for typed ingress clients (decision 8): `Reflection\HandlerSerdes` and the serdes it hands out (`Internal\Client\MappedJsonSerde`, `Internal\Client\BytesSerde`), and the JSON Value Mapping, which the endpoint and callers share: `JsonValueMapper`, `JsonValueMappingContext`, `JsonMappingException`, `Reflection\BuiltinJsonValueMapper`, `Reflection\DtoShapeFactory`, `Reflection\DtoShape`, `Reflection\DtoField` and the `JsonSchema\Attributes\JsonName` attribute they read.

   `IngressClientWithoutExtensionTest` fails when the ingress client starts loading anything else.
4. **One version for all packages, released together** (as Symfony and Laravel release their components). A `restate/*` package requires another with **`self.version`**, which Composer resolves to the requiring package's own version, in this repository and in split repositories alike; an installation therefore always has the same version of every `restate/*` package. That is what makes it safe for one package to use another's `@internal` types (`restate/ingress` and `restate/sdk` use `Internal\FlowControlKeys` and `Internal\TerminalMetadata` of `restate/common`): internal means internal to the set of `restate/*` packages, never to users (decision 11). A package that did not change in a release still gets the version. The cost is that a fix in one package cannot be released alone; with packages this coupled (`restate/common` exists only to be shared), lockstep is the simpler promise. `self.version` needs no branch alias: `dev-main` of one package requires `dev-main` of the others.
5. **`restate/sdk` requires `ext-restate` `~X.Y.0`**, the extension of its own minor version, released with it ([Release](0031-release.md)). `composer require restate/sdk` fails without the extension, which is the point of the split; a CI job that only analyses an application can pass `--ignore-platform-req=ext-restate`. `restate/ingress`, `restate/testing` and `restate/common` install without it. The runtime handshake (`BackendUnavailableException`) stays the check that knows about contract versions.
6. **Every package has `php: ~8.4.0 || ~8.5.0 || ~8.6.0`**, also those that never load the extension. The minors are what CI runs, all packages together ([Composer Metadata](0026-composer-metadata.md)); a wider constraint on `restate/ingress` would promise PHP versions nothing tests.
7. **The packages' requirements** (all `restate/*` with `self.version`; checked by decision 9):

   | Package | `require` | `suggest` |
   | --- | --- | --- |
   | `restate/common` | `php`, `ext-json` | |
   | `restate/sdk` | `php`, `ext-json`, `ext-restate` `~X.Y.0`, `psr/container` `^1.1 \|\| ^2.0`, `psr/http-factory` `^1.1`, `psr/http-message` `^2.0`, `psr/http-server-handler` `^1.0`, `psr/log` `^3.0`, `restate/common` | `cuyz/valinor`, `symfony/serializer`, `symfony/property-access`, `symfony/property-info` (the JSON payload adapters), `restate/ingress`, `restate/testing` |
   | `restate/ingress` | `php`, `ext-json`, `psr/http-client` `^1.0`, `psr/http-factory` `^1.1`, `restate/common` | `guzzlehttp/guzzle` |
   | `restate/testing` | `php`, `ext-filter`, `ext-json`, `psr/http-client` `^1.0`, `psr/http-factory` `^1.1`, `restate/common`, `restate/ingress` | `guzzlehttp/guzzle`, `guzzlehttp/psr7` (the default client and factories of `ingressClient()`), `phpunit/phpunit` (`PHPUnit\InteractsWithRestate`), `ext-pcntl` (stopping containers on Ctrl-C) |

   The test harness does not require `restate/sdk`: it serves the user's endpoint in a child process (`php -S` or a container), where the user's own installation has the SDK and the extension, and it names the module itself instead of reading SDK internals. `psr/http-message` is not a requirement of `restate/ingress`: its code names only the PSR-17 and PSR-18 interfaces.
8. **Typed ingress clients need only `restate/ingress` and `restate/common`.** A typed client of a service (a class with one method per handler, over the ingress client's requests) must write each handler's input and read its output as the endpoint does. Reflecting the service class at run time to find each handler's payload serdes would load 30 types outside `Restate\Ingress\` (service definitions, attributes, the context interfaces, the JSON Schema model), too much for a small common package. Instead such a client carries each handler's payload configuration as a `Reflection\HandlerSerdes` (built from a closure that declares the payload types, or from the payload's serde) and needs only `HandlerSerdes` and the JSON Value Mapping (decision 3); it does not load the service class either.
9. **Exact requirements, checked: `composer check:packages`** (part of `composer check`), `bin/check-packages.php`, run with the extension loaded:
   - `composer validate --strict` for each `packages/*/composer.json`;
   - **`shipmonk/composer-dependency-analyser`** per package over its `src/`: every class, function and constant the code names must come from the package itself, a package or extension it requires, or a third-party package or extension it suggests (optional code); and every requirement must be used. The analyser assumes one project with its own `vendor/`, so the script drives its `Analyser` directly: the dependencies come from the package's `composer.json`, Composer's class loader of the root is reused, and the repository root is passed as a second "vendor directory", so a class in `packages/<name>/src/` belongs to `restate/<name>`. With the extension loaded, `Restate\Extension\` resolves to `ext-restate`, so only `restate/sdk` may (and must) require it;
   - the root `composer.json` against the packages: it replaces each, autoloads each `src/`, and requires each third-party requirement with the same constraint and each suggested third-party package; packages are named `restate/<directory>` and require each other with `self.version`; no two packages define the same type; and no package declares anything in `Restate\Extension\`, the namespace the extension registers at startup, where a package type would be a fatal redeclaration or dead code;
   - the extension's PIE package and the release version ([Prebuilt Extension Binaries](0030-prebuilt-extension-binaries.md), [Release](0031-release.md)).

   Chosen over `maglnet/composer-require-checker` (it reports missing requirements only, not unused ones, and wants a `vendor/` per package) and over a PHPStan rule of our own (more code to maintain for the same answer). The dynamic counterpart is `PackagesLoadWithTheirRequirementsTest`: for each package, a `php -n` child (no extension) puts an autoloader in front of Composer's that only loads classes of the package, the `restate/*` packages it requires and their third-party requirements (transitively, as installed), and loads every type of the package; nothing may be refused.
10. **Tests: one PHPUnit configuration, unit tests attributed by directory.** `tests/Unit/<Package>/` holds each package's unit tests (`Common`, `Sdk`, `Ingress`, `Testing`; namespaces `Restate\Tests\Unit\<Package>\`), `tests/Unit/Packages/` and `tests/Unit/PHPStan/` the repository's own tooling. `tests/Extension/` is `restate/sdk`'s extension suite, `tests/Integration/` exercises the packages together against a real Restate, `tests/Support/` is shared (`Repository::ROOT`; `Packages` knows each package's directory and namespace). Tests stay outside `packages/`: they share fixtures across packages (the fake backend, the recording PSR-18 client, the harness), so a split repository could not run them on its own anyway, and `vendor/bin/phpunit tests/Unit/Ingress` runs one package's tests. The extension-free guarantees are stated per package: `IngressClientWithoutExtensionTest` and `PackagesLoadWithTheirRequirementsTest` (every package, `php -n`).
11. **The public API boundary works across packages.** [Public API Boundary](0016-public-api-boundary.md) is defined by namespace, so `PublicApiBoundaryRule` applies to every package, and each package's `Internal` namespace stays internal: `@internal`, never in a public signature. `restate/*` packages may use each other's internal types (decision 4); users may not.
12. **Releasing splits the repository**: `.github/workflows/release.yaml` splits each package directory and `extension/` into a read-only repository of its own and tags them all with the release version ([Release](0031-release.md)). Between releases, `.github/workflows/split.yaml` pushes each directory's history to its repository's `main` on every push to this repository's `main`, so `dev-main` follows it. A split repository's history starts where the directory's does.

## Consequences

- `composer require restate/sdk` refuses to install without the extension; `restate/ingress`, `restate/testing` and `restate/common` never need it. The root of this repository installs without the extension.
- Adding a dependency to a package means adding it to that package's `composer.json` and, with the same constraint, to the root; `composer check:packages` says which is missing. The root lists `guzzlehttp/psr7` and `ext-filter` because packages name them directly.
- Lockstep versions: one package cannot be released without the others.
