# Test Harness

## Status

Accepted. Builds on [Ingress Client](0022-ingress-client.md) and [Public API Boundary](0016-public-api-boundary.md). Decision 1 is amended by [Native Restate for the Test Harness](0038-native-restate-for-the-test-harness.md): Restate also runs as a process of the harness (`RestateProcess`), without a container runtime.

## Context

Users need a supported way to test their services against a real Restate server, and this repository's integration suite needs the same thing. Every official SDK ships one (TypeScript `492920d`, Java `6b0a96c`, Python `377d634`):

- **TypeScript** `@restatedev/restate-sdk-testcontainers`: `RestateTestEnvironment.start({services, container?, serviceEndpointAccess?, storage?})` serves the services in-process on a random port, starts a `RestateContainer` (Testcontainers `GenericContainer`; `host.docker.internal:host-gateway` by default, tmpfs storage), waits for `/restate/health`, `/health` and a `SELECT count(1) FROM sys_invocation` query (partitions ready), registers the endpoint, and exposes `baseUrl()`, `adminAPIBaseUrl()`, `stateOf(service, key)` (state read and written through the admin SQL API) and `stop()`.
- **Java** `sdk-testing`: a JUnit 5 extension (`@RestateTest`, `@BindService`) that starts Restate with Testcontainers and injects `@RestateClient Client`, `@RestateURL`, `@RestateAdminClient`.
- **Python** `restate.test_harness(app)` / `RestateTestHarness`: an ASGI server on a free port plus a Testcontainers `DockerContainer` with `extra_hosts={"host.docker.internal": "host-gateway"}`, one partition, and switches for always-replay (`RESTATE_WORKER__INVOKER__INACTIVITY_TIMEOUT=0s`) and disabled retries; `ingress_url()`, `admin_url()`, `ingress_client()`.

All three run the service in the test process. PHP cannot: a PHP endpoint is served by a web server, and the Restate extension must be loaded in that server's PHP. So the harness serves a **PHP entrypoint script** (the one production serves) with `php -S`, or runs it in a container.

### Testcontainers for PHP, evaluated

`testcontainers/testcontainers` (the PHP port, 1.2.1) was installed into a scratch project and used to start the Restate image under rootless podman:

| Question | Finding |
| --- | --- |
| Maturity | 1.x, active, but its sources carry TODOs around basics ("TODO: add withPullPolicy support", a `HostConfig` that is left null unless ports or mounts are set because the API "will throw … bad parameter"). |
| Dependency weight | 30 packages, 18 MB: `docker-php/docker-php` and a generated API client pinned to `docker-php/docker-php-api` `>=7.1.45.2,<7.1.46.0`, `jane-php` runtimes, `symfony/serializer`, `symfony/validator`, `symfony/yaml`, `symfony/process`, `symfony/filesystem`, `league/uri`, `php-http/*` (including `php-http/discovery`, a Composer plugin). A user's `require-dev` would have to resolve all of it against their own Symfony versions. The harness as built needs nothing. |
| Podman | Works only through the Docker API socket: `DOCKER_HOST` defaults to `unix:///var/run/docker.sock`, which rootless podman does not have, so the user must export `DOCKER_HOST=unix://$XDG_RUNTIME_DIR/podman/podman.sock`. That socket is socket-activated and its service exits after 5 s idle, which breaks Java Testcontainers runs (`bin/conformance-upstream-local.sh` starts a private `podman system service --time=0` for the upstream suite). The PHP port has no Ryuk, so no automatic cleanup either. With the socket set, **`StartedGenericContainer::logs()` failed under podman** ("Docker returned an error instead of the output stream"). Log dumps on failure are a requirement of this harness. |
| `host.docker.internal` | No `withExtraHosts()`; `ExtraHosts` would need a subclass overriding the protected `createHostConfig()` and building `docker-php-api` model objects. |
| Ports | `withExposedPorts()` binds `0.0.0.0` with a host port chosen client-side, i.e. Restate's admin API on the LAN. |
| Coverage | It would manage the Restate container only. The `php -S` endpoint, the extension preflight and endpoint containers stay the harness's job either way. |

## Decision

1. **The container CLI; no Testcontainers.** The harness runs `docker` (else `podman`, or `RestateContainer::withContainerRuntime()`) from an argument list, never a shell: `run --detach` with `--add-host host.docker.internal:host-gateway`, `logs --tail`, `rm --force --volumes`, `stop`, `kill`, `start`, `pause`. It works unchanged with Docker and rootless podman (no socket, no environment variables) and adds no dependency. Revisit if the PHP port grows extra hosts, loopback-only publishing and podman log support, and users ask to reuse their Testcontainers setup.
   - **Ports.** The harness picks two free loopback ports and publishes `127.0.0.1:<p>:8080` and `127.0.0.1:<q>:9070`, as it picks the endpoint's. An explicit mapping is part of the container's configuration, so a stop and start keeps it (daemon-chosen ports can move, as upstream's `KillRuntime.kt` warns). Another process can take a port between the choice and the bind, so a `run` that fails with "address already in use" or "port is already allocated" is retried with new ports, up to 5 times. An endpoint whose port was taken is started again: on a new port before registration, on the same one after.
   - **Storage** survives restarts: the container never has `--rm` or tmpfs, and Restate's data lives in `/restate-data` in its writable layer.
2. **Namespace `Restate\Testing\`, framework-agnostic at its core.** The configuration is three immutable value objects (private constructor, named constructors, `with…()` methods that validate their arguments and throw `\InvalidArgumentException`, public readonly properties):
   - `PhpCliServer::forScript($routerScript)`: `withExtension()`, `withPhpBinary()`, `withIniSetting()`, `withEnvironment()`, `withWorkers()` (default 8: a handler calling its own endpoint needs a second worker), `withBindAddress()`, `withDocumentRoot()`, `withWorkingDirectory()`, `withPath()`. Its `DEFAULT_INI_SETTINGS` are `display_errors=0`, `log_errors=1` and `enable_post_data_reading=0`, each replaceable with `withIniSetting()`. With PHP's built-in `display_errors=1`, any warning, deprecation or stray `echo` would land in front of the protocol frames ([Stray Output](0032-stray-output.md)); `display_errors=stderr` does not help under `php -S` (the SAPI is `cli-server`, and the message still goes into the response), while `log_errors` sends it to the server log, which is the endpoint log. `enable_post_data_reading=0` keeps PHP from parsing bodies into `$_POST`, so a journal over `post_max_size` raises no startup warning, and `php://input` still has the whole body; a bigger `post_max_size` would only move the cliff.
   - `EndpointContainer::forImage($image, $port = 8080)`: `withVolume()`, `withEnvironment()`, `withCommand()`, `withBindAddress()`, `withPath()`, `withHttp2()` (register over HTTP/2). The endpoint in a container, published on the bind address and reached through `host.docker.internal` like `php -S` (the repository's FrankenPHP and php-fpm runs use it; users can test their own image).
   - `RestateContainer::default()` / `forImage()`: `withEnvironment()` (Restate configuration, replacing the harness defaults: one partition, compact logs without ANSI codes), `withVolume()` (files that configuration points to, such as a request identity key), `withContainerRuntime()`, `withStartupTimeout()` (default 60 s).
   - `withRunArguments(list<string>)` on both containers adds options before the image name, accumulating like `withVolume()`, and refuses the options the harness owns (`--name`, `--rm`, `--detach`/`-d`, `--publish`/`-p`, `--publish-all`/`-P`).

   `RestateTestEnvironment::start($endpoint, ?$restate)` starts the endpoint and Restate, waits until they are ready (`waitUntilReady()`: admin `/health`, ingress `/restate/health`, a `sys_invocation` query, as TypeScript checks the partitions, and the endpoint's `/health`), then registers the endpoint (`POST /deployments`, `force`, HTTP/1.1 unless the container asks for HTTP/2). `RestateTestEnvironment::shared(...)` keeps one environment per configuration and process (one Restate per test run) and remembers a failed start instead of retrying it for every test. The environment exposes:
   - **URLs and clients:** `ingressUrl()`, `adminUrl()`, `endpointUrl()`, `endpointPort()`, `ingressClient(?PSR-18, ?PSR-17, ?stream factory, headers, ?Serde)`, `serverVersion()`.
   - **Registration:** `registerEndpoint($path = '')` (another endpoint the same server serves under a path) and `registerDeployment(string $uri, bool $http2 = false, bool $force = true)`, both returning the deployment id.
   - **Admin SQL:** `query(string $sql)` (throws `TestEnvironmentException` on a non-2xx response), `invocationRow(string $id, string ...$columns)` (null while Restate has no row; validates the column names and quotes the id) and `waitForInvocationStatus(string $id, string $status, float $timeout = 10.0)` (validates the status, fails with the last row it saw).
   - **Lifecycle, for failure injection:** `restartRestate(bool $graceful = true, int $stopTimeoutSeconds = 10)` (`stop --time`, or `kill --signal 9` then `wait`, then `start`, on the same container), `pauseRestate()`/`unpauseRestate()` (the cgroup freezer), `killEndpoint()`, `startEndpoint()`, `restartEndpoint(bool $graceful = false)`, `signalEndpoint(int)` (to the `php -S` process, or `kill --signal` for an endpoint container, which is how php-fpm gets `USR2`/`QUIT`) and `isEndpointRunning()`. A restarted endpoint keeps its port and is not registered again; a container gets a new name on every start, because `--rm` removal is asynchronous. A `php -S` server is killed together with its workers (listed from `/proc/<pid>/task/*/children` first), so no orphan keeps the port.
   - **Logs and names:** `endpointLog()`/`endpointLogSize()`, `restateLog()`, `dumpLogs()`, `containerRuntime()`, `restateContainerName()`, `endpointContainerName()` (for commands of the test's own, such as `docker inspect` or `exec`), and `stop()`.
3. **Extension.** `php -S` loads the module from `withExtension()`, else `RESTATE_PHP_EXTENSION_PATH`, else a module built from source under the project root (`extension/target/{debug,release}/restate.so` next to the project's `vendor/`, this repository's layout), else nothing and php.ini decides. "Loaded in the current process" is not used: an extension loaded with `php -d` on the command line is invisible to a child process, and PHP does not tell where it came from. A preflight builds an endpoint (`Endpoint::builder()->build()`, public API) in a throwaway PHP process with the same binary, extension and ini settings and the project's own autoloader, so a missing or mismatched extension fails with the SDK's own message. The harness names the module itself instead of reading SDK internals.
4. **Lifecycle and failures.** `start()` registers a shutdown function, so everything is removed by `stop()`, at process exit, or after a fatal error (which also dumps the logs). For Ctrl-C and SIGTERM it installs `pcntl` handlers that exit normally, but only where the process has not installed its own. Containers carry the label `restate-php-test-environment`. Every failure is a `Restate\Testing\TestEnvironmentException` (a `Restate\Exception`) whose message ends with the tail of the Restate and endpoint logs; a refused registration is its subclass `DeploymentRegistrationException` (`deploymentUri()`, `statusCode()`, `responseBody()`). The harness's own HTTP requests use PHP's stream wrapper (no curl, no PSR-18 client needed).
5. **PHPUnit is optional.** `Restate\Testing\PHPUnit\InteractsWithRestate` is a trait for any `TestCase` (PHPUnit 10+): implement `restateEndpoint()`, optionally override `restateContainer()`, call `self::restate()`. A `#[Before]` hook records the endpoint log offset and an `#[After]` hook dumps the logs when the test failed or errored, so it needs no base class and leaves `setUp()`/`onNotSuccessfulTest()` to the user. Nothing outside `Restate\Testing\PHPUnit\` references PHPUnit (`tests/Unit/Testing/TestingWithoutPhpUnitTest.php` fails if configuring or starting the harness autoloads a `PHPUnit\` class). `phpunit/phpunit` and `guzzlehttp/guzzle` (the default for `ingressClient()` without arguments, which Symfony's PSR-18 client cannot replace for handlers without input, see [Ingress Client](0022-ingress-client.md)) are suggested, not required.
6. **Its own package, `restate/testing`**, a dev dependency for users, like `@restatedev/restate-sdk-testcontainers` and `sdk-testing`. It requires `restate/ingress` and `restate/common`, **not `restate/sdk`**: the endpoint, with the SDK and the extension, runs in a child process with the project's own installation, so the test process needs neither ([Package Split](0029-package-split.md)).
7. **Public API boundary.** `Restate\Testing\` and `Restate\Testing\PHPUnit\` are public; `Restate\Testing\Internal\` (commands, processes, HTTP, extension lookup, validation) is internal. No `@internal` member is needed on a public type.

The repository's integration suite runs on it: `IntegrationTestCase` uses `InteractsWithRestate` with `tests/Integration/Support/IntegrationEndpoint.php`, which builds the `PhpCliServer` or, for the FrankenPHP and php-fpm servers, an `EndpointContainer` after its own preflight. `examples/testing/` (a user's endpoint and a PHPUnit test using only the public API) is part of the integration suite. Unit tests cover the command lines and validation, `ProcessTest` covers killing a real `php -S` with its workers, and `HarnessLifecycleTest` runs each lifecycle control once against Restate, in an environment of its own so the shared one is never restarted.

Not included: a state accessor like TypeScript's `stateOf()` (`query()` reads the `state` table), Java-style attribute injection, switches for always-replay or disabled retries (Python; `RestateContainer::withEnvironment()` passes the same server settings), tmpfs storage, and isolation between tests (they share one Restate; tests use fresh keys).

## Consequences

- Users test services against a real Restate with one trait and a script path, under Docker or rootless podman, without installing Testcontainers or configuring a Docker API socket.
- The endpoint listens on `0.0.0.0` by default so the container can reach it, which exposes it on the LAN for the duration of the tests; the README, the class docs and `TESTING.md` say so, and `withBindAddress()` / `RESTATE_PHP_TEST_BIND` narrow it.
- The harness's process and container handling is code this repository maintains, in exchange for no dependency.
- `RESTATE_PHP_RESTATE_IMAGE`, `RESTATE_PHP_EXTENSION_PATH` and `RESTATE_PHP_TEST_BIND` are public configuration: they replace defaults, explicit configuration wins.
