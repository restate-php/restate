# Ingress Client

## Status

Accepted. Builds on [Public API Boundary](0016-public-api-boundary.md) and [Exception Hierarchy](0015-exception-hierarchy.md).

## Context

PHP code that is not a handler (a web controller, a CLI command, a queue worker, a test) needs to invoke Restate services too, and the handler-side `ServiceClient`, `ObjectClient` and `WorkflowClient` need a handler `Context`. Every official SDK ships a standalone client for the Restate ingress.

What the official clients expose (TypeScript `492920d`, Java `6b0a96c`):

- **TypeScript** `@restatedev/restate-sdk-clients`: `connect({url, headers, fetch, serde, retry})` → `serviceClient(def)`, `objectClient(def, key)`, `workflowClient(def, key)` (proxies; `rpc.opts({idempotencyKey, headers, input, output})`, `rpc.sendOpts({delay})`), generic `call()`/`send()`, `result(send)` (attach), workflow `workflowSubmit()`/`workflowAttach()`/`workflowOutput()` (`{ready, result}`; 470 is "not ready"), `resolveAwakeable(id, payload, serde)`, `rejectAwakeable(id, reason)`. Errors: one `HttpCallError(status, responseText)`. An optional retry policy; `x-restate-error-source: invocation` makes an error non-retryable.
- **Java** `dev.restate.client.Client`: `call(Request)`, `send(Request, delay)` → `SendResponse` (`ACCEPTED`/`PREVIOUSLY_ACCEPTED`, and an invocation handle), `submit(WorkflowRequest)`, `invocationHandle(id)`, `idempotentInvocationHandle(target, key)`, `workflowHandle(name, id)`, each with `attach()` and `getOutput()` → `Output` (`isReady()`), `awakeableHandle(id).resolve()/reject(reason)`. Errors: one `IngressException(status, body, method, uri)` with the parsed `message`.

The ingress HTTP API, checked against Restate 1.8.1 (and 1.7.14, which answered identically): `POST /{service}[/{key}]/{handler}` calls; `…/send[?delay=500ms]` sends and answers 202 `{"invocationId", "status": "Accepted"|"PreviouslyAccepted"[, "executionTime"]}`; the `idempotency-key` header; `GET /restate/invocation/{id}/attach|output`, `GET /restate/invocation/{service}[/{key}]/{handler}/{idempotency-key}/attach|output`, `GET /restate/workflow/{name}/{key}/attach|output` (`output` answers 470 while running); `POST /restate/awakeables/{id}/resolve` (the value as the body) and `…/reject` (a `text/plain` reason). Errors are JSON `{"code", "message", "metadata"?, "source"}` with an `x-restate-error-source` header, `invocation` when the invocation failed (its terminal error, metadata included) and `ingress` when the ingress refused the request (unknown service 404, malformed id 400, 470). A handler without input requires an empty body **without** a content type (400 "Expected body and content-type to be empty" otherwise, also for an empty `Content-Type` value).

**There is no ingress route for signals.** Restate 1.8.1's ingress routes are `/restate/call|send|scope/…`, `/restate/invocation/…`, `/restate/workflow/…`, `/restate/awakeables/…` (and `/restate/a/…`); its admin API has cancel, kill, pause, resume, purge and restart for invocations but nothing for signals. Neither official client offers them. A signal is sent from a handler (`$ctx->invocation($id)->signal($name)`, [Named Signals](0019-named-signals.md)).

## Decision

1. **Namespace `Restate\Ingress\`, package `restate/ingress`**, which depends on `restate/common` and never on `restate/sdk` or the extension ([Package Split](0029-package-split.md)). The client uses only its own namespace and these shared types: `Serde`, `JsonSerde`, `Target`, `TerminalError` (with the pure helpers `Internal\TerminalMetadata` it validates metadata with and `Internal\FlowControlKeys` it validates scopes and limit keys with) and the `Exception` marker. It never touches the Backend Contract, the contexts, or the extension. `tests/Unit/Ingress/IngressClientWithoutExtensionTest.php` runs every operation in a `php -n` child process (no php.ini, no extension, only PHP's built-in modules) and fails if it loads a type of any other `restate/*` package.
2. **PSR-18 and PSR-17, wired explicitly.** The package `require`s `psr/http-client` and `psr/http-factory`. `IngressClient::connect(string $url, ClientInterface $httpClient, RequestFactoryInterface $requestFactory, ?StreamFactoryInterface $streamFactory = null, array $headers = [], ?Serde $serde = null)`; the stream factory defaults to the request factory when it implements both (Guzzle's `HttpFactory`, nyholm's `Psr17Factory`). No `php-http/discovery`: one explicit line instead of a Composer plugin and a dependency. Timeouts, TLS, proxies and retries are the HTTP client's configuration (Guzzle has a retry middleware), so the client has no retry policy of its own. The tests use `guzzlehttp/guzzle` (dev only).
3. **Empty bodies carry no content type.** A null payload is sent as an empty body, and a `Content-Type` from the connection or request headers is dropped for it, because Restate rejects any content type on the input of a handler without input. **Symfony HttpClient (`Psr18Client`) cannot call such handlers:** it adds `Content-Type: application/x-www-form-urlencoded` to every POST without one (curl does too; Symfony passes an empty header value through literally), which Restate rejects. Guzzle removes curl's default (`Content-Type:`), so the tests use it. Handlers with input work with any client.
4. **The API mirrors the handler-side clients, named like the official ingress clients.**
   - `serviceClient($name)`, `objectClient($name, $key)`, `workflowClient($name, $key)` → `request($handler, $payload = null)` → `ClientRequest` with `idempotencyKey()`, `header()`, `headers()`, `serde()`, `inputSerde()`, `outputSerde()` and `call()`, `send()`, `sendAfter($delayMillis)`: the shape of `$ctx->serviceClient()->request()` in a handler. The generic `call()`, `send()`, `sendAfter()` take a `Target` like `Context::call()`.
   - `send()` returns a `SendResponse` (`invocationId()`, `status()`: `SendStatus::Accepted|PreviouslyAccepted`, `invocation()`, `attach()`, `output()`), Java's shape; the request's output serde carries over to it.
   - `invocation($id)`, `idempotentInvocation(Target, $key)`, `workflowInvocation($name, $key)` return an `Invocation` with `attach()` (waits, `GET …/attach`) and `output()` (does not wait, `GET …/output`) → `Output` (`isReady()`, `value()`, which throws `\LogicException` when not ready) — Java's handles and TypeScript's `workflowAttach`/`workflowOutput`.
   - `WorkflowClient::submit($input)` sends `run`; `attach()`, `output()` read its result; `request()` reaches its shared handlers.
   - `resolveAwakeable($id, $value = null, ?Serde)`, `rejectAwakeable($id, string $reason)`.
   - **Unlike the handler-side `InvocationHandle`, whose `output()` waits** (and `peekOutput()` does not), the ingress `output()` does not wait. The ingress names follow the HTTP API and both official clients, and the different return type (`Output`, not the value) makes a mix-up fail loudly rather than silently.
   - Serdes are `Serde` instances (no class names), JSON by default, settable per connection and per request. A null payload is no input (TypeScript's `undefined`); an empty result decodes to null with the JSON serde. An awakeable value is always a value: null resolves it with JSON `null`, as `Context::resolveAwakeable()` does (a handler cannot decode an empty awakeable value).
5. **Errors: the invocation's failure is a `TerminalError`, everything else an `IngressException`.** When Restate attributes an error response to the invocation (`x-restate-error-source: invocation`, or the body's `source` if a proxy dropped the header) and it has a message and a 400–599 code, the client throws `Restate\TerminalError` with that code, message and metadata — the exception a handler gets from `$ctx->call()` for the same failure, so error handling can be shared. This includes Restate's own invocation-level failures, such as 409 for calling a workflow's `run` twice and 404 for attaching to a workflow that was never submitted (Restate attributes "not found" on attach to the invocation, as for an attach from a handler). Anything else — a transport failure (PSR-18 `ClientExceptionInterface`, no status), an error of the ingress (unknown service, malformed id), a response without an error source, a response that cannot be decoded, a malformed send response — is a `Restate\Ingress\IngressException` (`\RuntimeException`, implements `Restate\Exception`, not final): `statusCode()` (null without a response), `responseBody()`, `errorMessage()`, `errorSource()`, `requestMethod()`, `requestUri()`. 470 from `output()` is not an error but `Output::notReady()`. A failure of the payload serde while encoding propagates unwrapped (`\JsonException`, as on the handler side).
6. **Public API boundary.** `Restate\Ingress\` is public, `Restate\Ingress\Internal\` (the PSR transport) is internal. `Invocation::__construct` takes the internal transport and is the one `@internal` member (listed in `phpstan.neon` and [Public API Boundary](0016-public-api-boundary.md)); every other type is built from public types (`ServiceClient` and friends take the `IngressClient`, as the handler-side ones take the `Context`).
7. **Requests can be typed.** A typed client of a service (one method per handler returning a `ClientRequest` typed with the handler's output, with the handler's serdes from `Reflection\HandlerSerdes`) needs only `restate/ingress` and `restate/common` ([Package Split](0029-package-split.md)); the SDK ships none. For the types to flow, `ClientRequest`, `SendResponse`, `Invocation` and `Output` take a covariant template parameter defaulting to `mixed`. Such a client is per side: one class could not serve both, because a send returns an `InvocationHandle` in a handler and a `SendResponse` here.
8. **The [Test Harness](0023-test-harness.md) hands out an `IngressClient`** connected to the Restate it started (`RestateTestEnvironment::ingressClient()`, Guzzle by default).
9. **Scope and limit key.** `IngressClient::scope($scope)` returns a `Restate\Ingress\Scope` with the three client factories, `ClientRequest::limitKey()` sets a limit key, and the generic `call()`/`send()`/`sendAfter()` take a `Target::scoped()` target and `limitKey:`. Scoped requests go to `/restate/scope/{scope}/call|send/…` with the limit key in `x-restate-limit-key`; a scoped workflow's `attach()`/`output()`, `workflowInvocation(…, scope:)` and `idempotentInvocation()` of a scoped target look the invocation id up with `POST /restate/lookup` first (Restate has no scoped attach route). See [Scope and Limit Key](0024-scope-and-limit-key.md).

Not included: signals (no ingress route, see Context), client-side retries (the HTTP client's job), the invocation id and headers of a call's response (`x-restate-id`), the `executionTime` of a delayed send, invocation management (cancel, kill, pause, resume, purge: the admin API, not the ingress), Restate Cloud's `RESTATE_INGRESS_KEY` convention, and asynchronous (promise-based) calls.

## Consequences

- Plain PHP code can call, send (delayed, idempotent), attach, read outputs, run workflows and complete awakeables through any PSR-18 client, without the extension.
- Symfony HttpClient users cannot call handlers without input (Symfony adds a content type to every bodiless POST below the PSR-18 layer); documented in the README, which recommends Guzzle.
- The no-extension test keeps the client from growing dependencies on the rest of the SDK.
