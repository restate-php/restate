# PHP-FPM Serving

## Status

Accepted. Covers stray output and large bodies, the integration suite on php-fpm, and front-door hazards (length-less bodies, front-door timeouts shorter than Restate's, identity keys hidden by `clear_env`). Builds on [Stray Output](0032-stray-output.md) and the [Test Harness](0023-test-harness.md).

## Context

PHP-FPM behind nginx, Caddy or Apache is a common production shape for `Endpoint::serve()` ([SERVING.md](../serving.md)), and what a FastCGI front door does to Restate's requests matters: Restate 1.8.1 sends every invocation body without `Content-Length` (chunked over HTTP/1.1, plain DATA frames over h2c), php-fpm reads at most `CONTENT_LENGTH` bytes, and each front door handles a length-less body differently. Suites that run only under `php -S` and FrankenPHP prove none of that, nor serving with OPcache on or over h2c.

## Decision

1. **One image, three front doors.** `docker/Dockerfile` target `fpm-extension`: the official `php:8.4-fpm-trixie` (NTS) with the extension built inside it (debug by default, `EXTENSION_PROFILE=release` for a release module), nginx 1.26 and Caddy 2.11.9 (the `caddy-bin` stage, pinned instead of the floating `caddy:2`). `docker/fpm/entrypoint.sh` renders `docker/fpm/*.template` from `RESTATE_PHP_FPM_*` variables and runs php-fpm and the chosen front door in the foreground. Trixie, not bookworm: nginx 1.25.1+ serves h2c with prior knowledge and HTTP/1.1 on one port (`http2 on`), so the harness's HTTP/1.1 health checks reach an endpoint that Restate talks h2c to. `fpm-extension-apache` adds Apache httpd 2.4 (`mod_proxy_fcgi`) for the hazard tests only; `conformance-fpm-nginx` bakes the repository in and serves `test-services/index.php` on :9080 for the conformance suite.
2. **Production settings, not test settings.** `php.ini-production` with `docker/fpm/php.ini` on top: `display_errors=Off`, `log_errors=On`, `enable_post_data_reading=0`, `memory_limit=512M`, OPcache on (`validate_timestamps=1`, `revalidate_freq=0`: the repository is bind-mounted). The front doors get SERVING.md's settings: nginx `client_max_body_size 64m`, Caddy `request_buffers 64MiB`, Apache `SetEnv proxy-sendcl 1`, and read timeouts of 610 s (above Restate's 600 s abort timeout). A `defaults` profile drops all of them, so the hazard tests can show what the defaults do. The pool is `pm = static` with 8 children like `PHP_CLI_SERVER_WORKERS=8`, and runs as root (`php-fpm -R`) because the harness bind-mounts a state directory only its owner may write; `clear_env = no` as in the official images.
3. **Server values, not a new suite.** `RESTATE_PHP_TEST_SERVER` gains `nginx-fpm` (HTTP/1.1), `nginx-fpm-h2c` and `caddy-fpm` (both registered with `use_http_11: false`, `EndpointContainer::withHttp2()`); the whole integration suite runs on each (`just test integration <server>`, CI job `fpm`). A test that cannot run on a server skips with the reason (only `LargeBodyTest`'s `php -S` ini variants do).
4. **An empty `CONTENT_TYPE` or `CONTENT_LENGTH` is no header.** FastCGI front doors always pass both (nginx's stock `fastcgi_params`: `fastcgi_param CONTENT_TYPE $content_type;`), empty when the request had none. `HeaderMap::fromServer()` treats an empty one as missing, so an invocation without a content type gets the `415` the SDK answers elsewhere instead of reaching the VM and failing with `500` (`ServingTest`). Restate always sends a content type, so only direct requests are affected.
5. **Hazards are nightly.** The `serving-hazards` group (front doors at their defaults, timeouts, `clear_env`) and the `large-bodies` group (31 MiB, values over the 32 MiB message limit) are excluded from the PR suites in `phpunit.xml.dist` and run in `.github/workflows/nightly-serving.yaml`, with the conformance suite on `conformance-fpm-nginx`.

## Consequences

- The integration suite passes on all three FPM servers (only `LargeBodyTest`'s `php -S` ini variants skip), and so do the large-bodies group and the conformance suite on `conformance-fpm-nginx`, so PHP-FPM behind nginx or Caddy with the documented settings is tested, OPcache and h2c included. SERVING.md records the measured hazards; each one is a bounded, visible failure under a retry policy, and an endless retry without one, as the sources predicted.
- The FPM jobs build the image without a layer cache, like the FrankenPHP job: a few minutes of Rust build per job.
- `clear_env = yes` with a key from `getenv()` fails closed (the endpoint answers `500` to everything, `/health` included), as [identity keys](../serving.md#request-identity-validation) promise. The integration endpoint's own `RESTATE_PHP_TEST_IDENTITY_KEYS` is optional by design, so it would still run unverified under `clear_env = yes`; the hazard test uses its own router (`tests/Integration/Support/identity-from-env.php`) with SERVING.md's pattern.
- Signals to the container go to the entrypoint, which forwards `USR1`/`USR2` to the php-fpm master and stops gracefully on `QUIT` (the images' stop signal), so `signalEndpoint()` and `restartEndpoint(graceful: true)` reach php-fpm.
