# Troubleshooting

First failures when installing the Restate PHP extension and serving an endpoint.

| Problem | Likely Cause | Fix | Read More |
| --- | --- | --- | --- |
| `BackendUnavailableException`: The Restate PHP extension (restate) is not loaded, and restate/sdk … requires Restate PHP extension contract version N | An endpoint was built (`Endpoint::serve()`, `Endpoint::psr()`, `Endpoint::builder()->build()`) in a PHP process that did not load the extension. There is no other backend. | Install it with PIE: `pie install restate/ext-restate`, which also enables it (`extension=restate`). Check with `php -m` under the same PHP and SAPI that serves (php-fpm and the CLI can read different php.ini files): it must list `restate`. Where PIE has no prebuilt binary, build it from source. | [Installing the extension](../README.md#installing-the-extension) |
| The loaded Restate PHP extension … implements contract version N, but … requires Restate PHP extension contract version M | The extension and `restate/sdk` come from different versions, whose interfaces between them differ. | Do what the message says: when the extension is older, install the version that matches the package (`pie install restate/ext-restate:<version>`); when it is newer, upgrade `restate/sdk` or install the extension that matches it. Restart the PHP server afterwards: a running server keeps the module it started with. | [Extension Versions](EXTENSION_VERSIONS.md), [Serving](SERVING.md#php-extension) |
| PIE finds no prebuilt archive for your platform | Prebuilt binaries cover Linux x86_64 and arm64 with glibc 2.28+ or musl, PHP 8.4, 8.5 and 8.6, NTS and ZTS, but not macOS, Windows or debug builds of PHP. | Build the extension from source. | [Installing the extension](../README.md#installing-the-extension) |
| PIE installs the extension but cannot enable it ("Expected extension restate to be loaded … but it was not detected"), or PHP reports ``version `GLIBC_2.xx' not found`` or a missing `libgcc_s.so.1` | The system's glibc is older than 2.28, or a minimal Alpine lacks `libgcc`, which the module needs. | On Alpine, `apk add libgcc`. With an older glibc, build from source on that system. | [Prebuilt Extension Binaries](decisions/0030-prebuilt-extension-binaries.md) |
| PHP refuses to load the extension (build ID or API mismatch) | The module was built for another PHP minor or thread-safety mode, for example an NTS build loaded into FrankenPHP's ZTS PHP. | Install it with PIE into the PHP that serves, which picks the matching build. From source, build against that PHP: `bash bin/build-extension.sh --release --php-config <that PHP's php-config>`. | [Serving](SERVING.md#php-extension) |
| A build from source fails with `'stdlib.h' file not found` | bindgen cannot find the C headers: in a checkout of this repository, the build ran outside the dev shell, which sets `BINDGEN_EXTRA_CLANG_ARGS`. | Run the build inside `devenv shell`, or set `BINDGEN_EXTRA_CLANG_ARGS` to your compiler's include flags. | [CONTRIBUTING.md](../CONTRIBUTING.md#building-the-extension) |
| Registering the deployment fails | Restate cannot reach the endpoint (a server bound to `127.0.0.1` is not reachable from a container), or talks HTTP/2 to a server that speaks only HTTP/1.1, such as `php -S`. | Bind the endpoint to an address Restate reaches (for Restate in Docker, `0.0.0.0` and `host.docker.internal`), check that `/health` answers from there, and register an HTTP/1.1 server with `"use_http_11": true`. | [Quickstart](../README.md#quickstart) |
| Registration fails with `META0003 got status code '401 Unauthorized'` | The endpoint has identity keys, and Restate does not sign its requests with the matching private key. | Give Restate the private key whose public key the endpoint trusts. Under PHP-FPM, check that `clear_env` does not hide the key's environment variable. | [Request Identity Validation](SERVING.md#request-identity-validation) |
| Every attempt fails with `unexpected content type` (RT0012) | PHP printed a warning or notice before the endpoint ran (for example a request body over `post_max_size`), with `display_errors` on. | Set `display_errors=Off` with `log_errors=On`, and `enable_post_data_reading=0`. The endpoint's log names where the output started. | [PHP Settings](SERVING.md#php-settings) |
| Behind PHP-FPM, attempts fail above some journal size (`411`, `413`, or `571 Protocol violation: The input was closed …`) | Restate sends request bodies without a length, and the front door's defaults do not buffer them (Caddy above 4 KiB, Apache above 16 KiB, nginx above 1 MiB). | Apply the front-door settings for your server. | [PHP-FPM and FastCGI](SERVING.md#php-fpm-and-fastcgi) |
| An attempt fails with code 573 and "… needs service protocol v7 (Restate 1.8 or newer) …" or "Feature … is not supported …" | A feature of Restate 1.8 (pausing, scopes and limit keys) used against Restate 1.7. | Upgrade Restate to 1.8 or newer. | [Shared Core](decisions/0014-shared-core.md#server-compatibility) |
| Handler throws an exception and the invocation keeps retrying | Any exception other than `TerminalError` is reported as retryable, including a `\JsonException` from handler code or from encoding the output. Only undecodable handler input is a terminal `400`. | Throw `TerminalError` for expected business failures, or map exceptions with an error mapper. | [Error handling](../README.md#error-handling-in-handlers) |

## Reporting a Bug

If the failure is not listed here, open an issue with:

- The PHP version, SAPI and thread safety: `php -v` (ZTS builds say so) and how you serve (`php -S`, PHP-FPM behind which front door, FrankenPHP classic or worker mode, a PSR-15 framework).
- The extension version: `php --ri restate`, or `Restate\Extension\version()` from the serving PHP, and the `restate/sdk` version (`composer show restate/sdk`).
- The Restate server version (`restate-server --version`, or the image tag).
- The operating system, CPU architecture and libc (glibc or musl).
- What you did and what happened: the command or the invocation, the full error, the endpoint's log (give the endpoint a [PSR-3 logger](../README.md#logging)), and Restate's log around the failure.
